# B3-1 실행 계획: 같은 데이터로 B3-2까지 연결

갱신: 2026-10-19. 기준: [과제 원문](과제문.md) 1~5절과 사용자의 동일 데이터 연계 요청.
공식 자료 확보·분석 코드·리포트·그래프와 로컬 검증을 완료했다. GitHub 제출과 개인 설명 능력은 별도 상태로 관리한다.

## 1. 목표와 연결 방식

B3-1에서 시계열 데이터를 정제·분석해 근거 있는 리포트를 완성하고, 같은 정제본을 B3-2 AI 비서의 초기 데이터로 사용한다.
사용자 선택에 따라 **2025년 따릉이 대여·서울버스 승차·공개 지하철 승차의 일별 시계열**로 변경한다. 날짜마다 수단별 3행인 하나의 비교 데이터셋을 만든다. 지하철에는 수도권 역, 서울버스에는 시외 정류장이 포함될 수 있으므로 서울 행정구역 내부 이동이나 고유 이용자 수로 해석하지 않는다.

```text
Seoul public CSVs
     |
     v
B3-1: clean -> observations.csv + manifest.json
     |                    |
     v                    v
analysis -> charts    exact-copy seed -> B3-2 Firestore
     |                                      |
     v                                      v
REPORT.md                             summary -> AI chat
```

원본과 정제본의 생산 책임은 B3-1에 둔다. B3-2 초기 적재 시 정제본의 해시·행 수·기간·값이 같은지 확인한다. B3-2의 이후 CRUD는 DB만 변경하고 B3-1 분석 자료를 덮어쓰지 않는다.

## 2. 원문 요구사항과 완료 기준

| 구분 | 원문 기준 | 완료 증거 |
|---|---|---|
| 필수: 주제·자료 | 시계열 데이터 1개, 100개 이상, 출처·기간 명시 | 원본과 정제 결과의 개수·기간, 출처 기록 |
| 필수: 질문 | 분석 질문 3개 이상 | REPORT.md의 질문과 각각의 답 |
| 필수: 품질 | 기간·컬럼·결측치 확인, 결측치/이상치가 있으면 기준에 따라 처리 | quality.json과 리포트의 처리 내역 |
| 필수: 분석 | 시계열 기법 2가지 이상 | 이동평균·기간별 집계 코드와 실제 결과 |
| 필수: 시각화 | 리포트에 그래프 2개 이상, 링크 정상 | PNG 파일과 렌더링된 리포트 |
| 권장 | 그래프 총 3개 이상 | 이번 계획은 4개 생성 |
| 필수: 인사이트 | 3개 이상, 각각 관찰·수치·그래프 근거 포함 | 인사이트와 statistics.json 대조 |
| 필수: 리포트 | 주제·질문·데이터 설명·시각화·인사이트·결론/한계점 | REPORT.md의 6개 내용 |
| 필수: 코드 | .py 또는 .ipynb, 입력 자료 또는 수집 스크립트 | 실행 가능한 Python 코드와 데이터 확보 방법 |
| 필수: 제출 | GitHub에 코드·리포트·가능한 데이터 또는 수집 방법 | 원격 저장소와 이미지 링크 |
| 학습 목표 | 질문·정제·트렌드/계절성/노이즈·분석 방법·AI 검증을 설명 | 설명 자료 준비 후 사용자 확인 |
| 이번 연계 기준 | B3-1 정제본 = B3-2 최초 적재 자료 | 파일 SHA-256, 행별 값, 기간·건수·기본 통계 비교 |

유효 관측값도 100개 이상이어야 다음 단계로 진행한다. 마지막 연계 기준은 사용자의 요청을 구현한 설계 규칙이며 원문에 추가된 과제 조건이 아니다.

## 3. 질문·분석·그림

| 질문 | 분석 | 그림·근거 |
|---|---|---|
| 평일과 주말의 수단별 이용량은 어떻게 다른가? | 요일별 평균·주말 증감률 | 02_weekday_patterns.png |
| 월별 이용량과 변동 폭은 어떻게 다른가? | 월별 일평균·연평균=100 지수 | 03_monthly_patterns.png |
| 같은 요일의 평소보다 이용량이 크게 달라진 날은? | 월×요일 기준 편차·수단 간 비교 | 04_unusual_days.png와 날짜별 근거 |

01_daily_trends.png에는 원시 일별 값과 7일 이동평균을 표시한다. 월×요일 기준은 사후 탐색용이며 미래 예측·인과 추론이 아니다. 공휴일도 평일/주말 분류에는 달력 요일 그대로 포함한다.

관측값을 계산한 뒤 결론을 쓴다. 변화는 건수와 증감률로 표현하고, 관찰된 변화와 원인에 대한 가설을 구분한다.

## 4. 실행 순서

| 순서 | 작업 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 1 | 공식 자료 확보·출처·단위·공유 범위 확인 | 실제 CSV 확인, 유효 관측값 100개 이상 |
| 2 | 날짜·중복·누락·결측·이상치 점검 | 처리 기준과 전후 개수 기록 |
| 3 | 정제본·manifest 생성 | 데이터 계약 검증과 해시 기록 |
| 4 | 분석 코드·그래프 4개 작성 | 대표 수치 별도 계산, 그림 축·단위 확인 |
| 5 | REPORT.md 작성 | 질문 3개에 답하고 인사이트 3개 이상에 근거 연결 |
| 6 | 새 실행으로 재현·제출 점검 | 수치 일치, 이미지 링크 정상, GitHub 파일 확인 |
| 7 | B3-2로 같은 정제본 전달 | 인계 파일의 바이트 일치 확인. DB 대조는 B3-2 구현 시 수행 |

자료 경로: [따릉이 일별 총대여](https://data.seoul.go.kr/dataList/OA-14994/F/1/datasetView.do), [버스 일별 승하차](https://data.seoul.go.kr/dataList/OA-12912/S/1/datasetView.do), [지하철 일별 승하차](https://data.seoul.go.kr/dataList/OA-12914/F/1/datasetView.do). 공개 CSV를 내려받아 승차만 집계한다. 원본 다운로드 주소·해시·행 수를 기록하고 대용량 원본은 Git에서 제외한다. 공식 자료의 지역 범위·집계 기준 차이를 보존하며 상관관계를 환승·대체 효과로 단정하지 않는다.
