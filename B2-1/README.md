# 나만의 프롬프트 관리

Python 콘솔에서 프롬프트를 추가하고 카테고리·키워드·즐겨찾기로 찾아보는 입문용 프로그램입니다. Python 기본 문법과 리스트·딕셔너리를 사용하며, 외부 라이브러리 설치가 필요하지 않습니다.

## 실행 방법

Python **3.10 이상**이 필요합니다. 현재 환경에서는 Python 3.13.1로 검증했습니다. 저장소 루트에서 실행하려면:

```bash
cd B2-1
python3.13 main.py
```

이미 `B2-1` 폴더의 터미널을 열었다면 `python3.13 main.py`만 실행하세요. `python3 --version`이 3.10 이상이라면 `python3 main.py`도 사용할 수 있습니다. 셸에 따라 `python3`이 3.9를 가리킬 수 있으므로 버전을 먼저 확인하세요. 메뉴 번호를 입력하고 Enter를 누릅니다. 제목과 내용은 각각 한 줄로 입력합니다.

## 기능

| 번호 | 기능 |
| --- | --- |
| 1 | 제목·내용·카테고리를 입력해 프롬프트 추가 |
| 2 | 전체 프롬프트의 번호·제목·카테고리·즐겨찾기 표시 |
| 3 | 카테고리별 조회 |
| 4 | 제목 또는 내용에 포함된 키워드 검색 (영문 대소문자 무시) |
| 5 | 번호로 선택한 프롬프트의 전체 내용 확인 |
| 6 | 번호로 선택한 프롬프트의 즐겨찾기 등록·해제 |
| 7 | 즐겨찾기 목록 조회 |
| 0 | 종료 |

빈 제목·내용·검색어는 다시 입력받습니다. 잘못된 메뉴·프롬프트 번호에는 안내를 출력합니다. 검색 및 필터 결과에서도 전체 목록의 원래 번호를 유지하므로 그 번호를 상세 보기와 즐겨찾기 관리에 사용할 수 있습니다.

메뉴·카테고리·프롬프트 번호는 같은 검증 함수를 사용합니다. 앞뒤 공백과 앞자리 0을 허용하여 `02`도 `2`로 처리하며, 문자·음수·범위를 벗어난 번호는 안내합니다. 매우 긴 숫자도 예외 없이 거절합니다.

추가 데이터와 즐겨찾기 변경은 **현재 실행 중에만 유지**합니다. 종료 또는 입력 중단 후 다시 실행하면 기본 데이터로 돌아갑니다. JSON 저장, 내보내기, 수정·삭제, 조회수·인기순 정렬은 구현하지 않았습니다.

## 카테고리와 기본 데이터

카테고리는 `텍스트 생성`, `이미지 생성`, `영상 생성`, `페르소나`, `자동화`, `기타` 중 선택합니다.

| 기본 번호 | 제목 | 카테고리 |
| --- | --- | --- |
| 1 | 공고도우미 v1 일반 요약 | 텍스트 생성 |
| 2 | 공고도우미 v2 단계적 요약 | 텍스트 생성 |
| 3 | 공고도우미 최종 시스템 프롬프트 | 페르소나 |

기본 데이터의 내용은 실제 이전 미션 보고서인 [시스템 설계 문서](../B1-1/내_보고서/시스템%20설계%20문서.md)의 **9-1절 v1**, **9-2절 v2**, **11절 최종 시스템 프롬프트** 전문을 그대로 등록했습니다. 제목과 카테고리는 식별하기 위해 지정했습니다. 코드의 `content`와 보고서의 코드 블록을 공백·줄바꿈을 포함해 비교하여 3개 모두 일치하는 것을 확인했습니다. 이 프로그램은 프롬프트를 보관·조회하며, 프롬프트 안의 URL에 접속하거나 AI에게 실행을 요청하지 않습니다.

## 코드 구조

- `main.py`: 메뉴 반복, 기본 데이터, 입력 검증, 기능별 함수
- `과제문.md`: 원본 과제의 본문과 요구사항
- `요구사항_체크리스트.md`: 각 요구사항의 완료 여부와 확인 근거
- `docs/evidence/검증_로그.md`: 현재 코드로 실행한 CLI 시나리오와 Git·환경 점검 결과

`main()`에서 만든 리스트를 각 기능에 전달합니다. 각 항목은 `title`, `content`, `category`, `favorite` 필드를 가진 딕셔너리이며, 새 항목의 `favorite` 기본값은 `False`입니다.

별도의 `tests/` 폴더는 없습니다. 검증 로그에 기록한 입력을 `python3.13 -B main.py` 실행 후 순서대로 입력하면 콘솔 흐름을 다시 확인할 수 있습니다. 실제 검증에 사용한 실행 파일은 `/opt/homebrew/opt/python@3.13/bin/python3.13`입니다. `-B`는 캐시 파일 생성을 방지합니다.

## 제출용 스크린샷 순서

개발 환경·프로그램 화면은 사용자가 완료를 확인한 팀원 제공 자료를 유지합니다. `screenshots/1.png`와 `3.png`의 출처는 팀원이며 이번 대화에서 새로 촬영한 자료는 아닙니다. 아래 순서는 화면을 추가로 확인할 때의 참고 절차이며 별도 실습·재촬영을 요구하지 않습니다. `screenshots/4.png`에는 사용자가 직접 촬영한 Python 버전, Git 버전·사용자 설정, 기본 브랜치와 현재 브랜치, Hello 출력이 있습니다. 재촬영할 때는 `B2-1` 폴더의 터미널에서 아래 명령어를 실행합니다. 옵션에는 긴 대시(`—`) 대신 일반 하이픈 두 개(`--`)를 사용합니다.

```bash
python3 --version
git --version
git config user.name
git config user.email
git config --get init.defaultBranch
git branch --show-current
python3 -c 'print("Hello")'
```

현재 [개발 환경 확인 이미지](screenshots/4.png)는 사용자가 터미널에서 위 명령어를 실행해 직접 촬영한 원본입니다. Python 3.13.1, Git 2.50.1, Git 사용자 설정, 기본·현재 브랜치 `main`, `Hello` 출력을 확인할 수 있습니다.

프로그램 화면은 아래 순서대로 **한 번의 실행에서** 찍으면 됩니다. 각 기능 결과는 다음 메뉴 바로 위에 표시됩니다.

| 순서 | 입력 | 촬영할 화면 |
| --- | --- | --- |
| 1 | `python3.13 main.py` 실행 | 전체 메뉴 |
| 2 | `1` → 제목 `회의 요약` → 내용 `회의 내용을 세 문장으로 요약해주세요.` → 카테고리 `1` | 입력 내용과 추가 완료 메시지 |
| 3 | `2` | 기본 3개와 새 항목 4번이 있는 전체 목록 |
| 4 | `3` → `1` | 텍스트 생성 카테고리 결과 |
| 5 | `4` → `회의` | 새 항목 4번이 포함된 검색 결과 |
| 6 | `5` → `4` | 제목·카테고리·즐겨찾기·전체 내용 |
| 7 | `6` → `4`, 이어서 `7` | 즐겨찾기 등록 메시지와 별표가 있는 목록 |
| 8 | `6` → `4`, 이어서 `7` | 즐겨찾기 해제 메시지와 빈 목록 안내 |
| 9 | `0` | 정상 종료 메시지 |

과제에서 명시적으로 예시를 든 실행 화면은 메뉴·추가·목록·검색이며, 나머지는 기능 증빙용으로 함께 촬영하는 것을 권장합니다. 정확한 장수는 지정되지 않았습니다. 글자가 읽히도록 나누어 찍으세요.

Git 기록은 다음 명령어로 표시한 뒤 본인의 현재 저장소 기록을 촬영합니다. 2026-10-07 점검 시 전체 커밋은 6개, `B2-1`을 변경한 커밋은 1개이며 병합 커밋은 없습니다. 원문의 커밋 10개 이상 및 목록 기능의 브랜치 작업·로컬 병합 요구사항은 아직 미충족입니다. 기존 `screenshots/2.png`에 표시된 다른 Git 기록은 현재 저장소에 없으므로 완료 증거로 사용하지 않습니다. 실제 필요한 기능 변경을 의미 있는 단위로 작업하며 기록을 쌓아야 합니다.

```bash
git --no-pager log --oneline --graph -15
```

## Git 작업 범위

기존 상위 저장소의 원격 연결과 루트 `.gitignore`를 사용합니다. 현재 브랜치는 `main`이며, `origin`은 위 제출 저장소를 가리킵니다. 이번 요구사항 점검에서는 Git 기록을 읽기만 했습니다.

현재 `git log`와 `reflog`에서 기존 커밋 및 푸시 기록은 확인했습니다. 현재 사용자가 `init`, `add`, `pull`, `checkout`, 공개 샘플 저장소의 `clone`, 로컬 `merge`를 수행했다는 명령 기록은 확인하지 못했습니다. 커밋에 파일이 포함된 사실만으로 `git add` 명령 사용까지 증명하지 않았습니다. 이 항목은 [요구사항 체크리스트](요구사항_체크리스트.md)에 확인 대기로 표시했습니다. 없는 작업 기록이나 가져온 스크린샷으로 완료 여부를 대신 판단하지 않습니다.
