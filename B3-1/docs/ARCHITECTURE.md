# 이번 분석 코드의 책임과 의존성

```text
run_od_analysis.py  실행 순서·실패 시 중단
  references       공식 ID 연결, 역사적 이름·코드, 고정 비교 지역
  prepare          원본 읽기·숫자/중복 검증·유입/유출 검산·월별 집계
  audit_aliases    같은 지역 ID의 동시 출현 검사, 전 기간 제외 목록
  audit_presence   모든 관측일의 지역 존재 교집합, 전 기간 제외 목록
  calendar         공식 달력과 후속 공지 → 가공 달력
  analyze          결측/이상일, 이동평균, 월×요일 표준화, 변화율·민감도
  report           집계표 → PNG·Markdown·HTML (원본 접근 없음)
  verify           별도 CSV 계산, 해시·이미지·링크 검증
```

원본은 읽기만 한다. 계산 모듈은 표를 만들고, 보고서 모듈은 표에서 수치를 읽는다. 숫자를 리포트에 수동으로 옮겨 적지 않는다. 시간대·범위·동일 지역 내부 이동 처리 규칙은 계획과 데이터 사전에 명시한다.

처음 실행은 참조에 따른 집계로 코드·관측 문제를 찾고, 공통 패널을 확정한 뒤 가공본을 재계산한다. 제외 목록이 존재하면 처음부터 고정 패널을 적용한다. 캐시는 원본·지역 매핑·가공본 해시와 명시적 버전으로 검증한다. 정제 알고리즘이 달라지면 `common.VERSION`을 올려 캐시를 무효화한다.

실제 원본의 숫자 형식 오류는 숨기지 않고 실행을 멈춘다. `prepare.lock`으로 동시 실행을 막고, 다른 과제 파일을 읽거나 수정하지 않는다. 예전 `analysis/` 패키지는 의존하지 않는다.
